## New database compatibility

- `campaign_plans.optimization_mode` is additive, non-null, and defaults to the conservative `approval_required` behavior for every existing row.
- `ai_usage_events` is a new service-role-only table with RLS enabled and no authenticated/anonymous policies. It stores no prompts, generated content, credentials, or raw provider payloads.
- No auth, user, membership, entitlement, invoice, payment, Stripe, webhook, or existing client-data table is rewritten.
- Rollback is isolated: application code tolerates unavailable telemetry; the added table and campaign column can be removed without changing existing campaign items or billing data.

## Release boundaries

- GitHub is the source of truth and must be committed/pushed/verified before any Lovable action.
- This release intentionally does not claim native iOS/Android device testing, store submission, voice support, autonomous campaign mutation, marketplace licensing, or real-account third-party API validation without the required accounts/devices.
- Automatic Optimization records user intent only. It does not silently edit or publish anything in this release; existing publishing confirmation and approval safeguards remain authoritative.
