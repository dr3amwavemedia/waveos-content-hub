# Lovable handoff: Documents layout and client-specific contracts

Use the latest `codex/documents-contract-builder` GitHub branch as the source of truth. Do not replace its Documents page layout, contract variable renderer, client contract editor, or additive migration. The live and preview URLs currently share a backend with real client data; prepare an isolated test backend with synthetic clients before testing creation or applying `supabase/migrations/20260915062048_contract_variable_snapshot.sql`. Do not send signing requests or client emails during this test.

Verify the Documents dashboard uses a wide layout with separate Invoice items, Contracts, and Forms category cards. Opening an editor should focus on that editor rather than crowding it with the saved list. Check desktop and mobile widths and keyboard access.

In the isolated backend, create a contract template with `{{client_name}}`, `{{business_name}}`, `{{services}}`, `{{project_date}}`, `{{today_date}}`, `{{location}}`, and `{{project_name}}`. From one client profile, choose the template and verify current workspace/CRM client and business details fill automatically. Select that client's project and invoice items; verify the filled preview shows the chosen services, quantities and prices. Edit every variable and the wording, replace starter clause prompts, and save a private draft. Reopen and edit it; verify its values and wording remain as saved even after the template is changed. Repeat for a second client and confirm no details or invoice items cross clients. Confirm the draft remains invisible to client accounts and no signature request is created. Test unsupported or empty variables and missing migration errors.

Confirm the stored contract has the selected `workspace_id`, rendered `description`, `contract_data` snapshot, and template ID/version. Check the existing SignWell send path uses that rendered description only after a separately reviewed publication step. Report the migration result, role/RLS tests, UI checks, and any remaining release work. Do not migrate the shared live backend or enable real signing in this run.
